# “青缝长图拼接”获客与转化路径研究

日期：2026-07-29

范围：微信小程序正式版 `0.1.3` 的公众推广，以及站外内容平台向微信小程序导流。

原则：不虚构流量数据；只把已确认的平台能力写成“可用”，无法从官方公开材料确认的能力写成条件项。

## 结论先行

目前最可靠的公众转化链路不是体验版分享，而是：

> 场景短视频/图文种草 → 展示完整名称“青缝长图拼接”与正式小程序码 → 用户微信搜索或扫码 → 首屏立即选图 → 完成一次拼接并保存

优先级建议：

1. **微信搜索 + 正式小程序码**：现在就能做，也是阻力最小的公众入口。
2. **视频号内容 + 小程序码/搜索指令**：与微信处在同一生态，适合用短录屏展示“拼接前后”。
3. **公众号图文/菜单**：仅在拥有并能关联公众号时投入；可形成可重复访问的教程入口。
4. **小红书、抖音、B站内容矩阵**：作为发现渠道，默认使用“完整名称搜索 + 小程序码”的双 CTA，不把普通帖子能否直接唤起微信小程序当成确定能力。
5. **腾讯广告**：技术上存在以小程序为落地页的付费路径，但应在自然流量已验证首轮转化后再测试，避免先买曝光、后发现首屏或素材不转化。

`0.1.4` 体验版不适合作为公众推广落地页：体验版用于内测，访问对象是体验成员；正式版才面向普通用户。当前线上 `0.1.3` 可继续被公众搜索和使用，失败或删除的审核版本不影响它。

## 证据边界

### 已确认

- 微信官方提供小程序搜索索引配置：`sitemap.json` 用于决定小程序页面是否允许被微信索引。允许索引只代表“可能进入搜索结果”，不代表固定排名或保证曝光。[微信开放文档：sitemap 配置](https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/sitemap.html)
- 微信官方提供小程序码接口，包括适合大量场景码的“不限制的小程序码”；小程序码可指定正式版、体验版或开发版环境。公众宣传应使用正式版（`release`）。[微信开放文档：获取不限制的小程序码](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/qrcode-link/qr-code/getUnlimitedQRCode.html)
- 微信提供 URL Link 和 URL Scheme，用于从短信、邮件、网页等场景拉起小程序；两项能力都有主体资格、生成数量、有效期、调用方式等条件，必须按当前后台权限核验后使用，不能等同于“所有内容平台都允许粘贴并直接跳转”。[微信开放文档：URL Link](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/qrcode-link/url-link/generateUrlLink.html)；[微信开放文档：URL Scheme](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/qrcode-link/url-scheme/generateScheme.html)
- 微信小程序页面存在好友转发和朋友圈能力，但具体页面需要按官方分享接口配置，并受平台审核和运营规范约束。[微信开放文档：Page](https://developers.weixin.qq.com/miniprogram/dev/reference/api/Page.html)；[微信开放文档：分享到朋友圈](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/share-timeline.html)
- 公众号自定义菜单接口支持 `miniprogram` 类型，可配置要打开的小程序 `appid`、页面路径和备用网页；前提是公众号具备相应能力并与小程序完成关系配置。[微信公众平台开发文档：创建自定义菜单](https://developers.weixin.qq.com/doc/offiaccount/Custom_Menus/Creating_Custom-Defined_Menu.html)
- 小程序可通过 `button open-type="contact"` 让用户主动进入客服会话。客服是答疑、收集反馈和促成复访的工具，不是可无条件群发的冷启动流量池。[微信开放文档：button](https://developers.weixin.qq.com/miniprogram/dev/component/button.html)；[微信开放文档：客服消息](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/customer-message/customer-message.html)
- 腾讯广告官方材料显示，小程序可以作为微信广告落地页，朋友圈、公众号/小程序等广告资源可形成微信内转化链路；投放资格和实际可选版位以腾讯广告账户为准。[腾讯广告培训材料：小程序转化路径与玩法](https://training.tencentads.com/uploads/202203/jyNjfLnM_Q2fIFB.pdf)

### 当前项目事实

- 正式在线版本为 `0.1.3`；它已经上线，普通用户通过微信搜索或正式小程序码进入该版本。
- `0.1.4` 固定首页分享版本未通过代码审核；删除审核版本不会删除线上 `0.1.3`。
- 若 `0.1.4` 仍被设置为体验版，只有具备体验权限的微信账号能把它当作测试版本使用。它不能替代正式版承担公众转化。
- 项目的核心承诺是“用户图片仅在本机处理，不上传”。任何后续增长功能不得把用户原图或拼接结果上传到服务器，除非同时重新评估产品承诺、隐私指引和审核要求。
- 当前项目没有 `sitemap.json`。微信官方说明未配置时默认允许全部页面被索引；因此不必仅为增加该文件而发布新版本，但仍需在公众平台确认全局“页面收录/允许被搜索”开关没有关闭。
- 当前项目没有渠道归因或步骤漏斗上报代码。第一阶段先使用公众平台自带的访问与来源数据；若未来加入 `wx.reportEvent`，只上报渠道码和“开始选图/拼接成功/保存成功”等匿名事件，绝不携带原图、文件路径、图片内容或个人信息，并作为单独版本重新评估隐私与审核。

### 未确认或必须按账号现场核验

- 未确认当前小程序主体是否具备 URL Link、URL Scheme、视频号主页“服务”入口或腾讯广告投放资格。微信官方的加密 URL Link 接口目前注明仅面向国内非个人主体；若“青缝长图拼接”是个人主体，不应把 URL Link 作为近期方案。
- 未找到足够的一手公开证据证明：普通小红书笔记、普通抖音视频文案或普通 B 站稿件中的链接，可以稳定地直接唤起微信小程序。因此不能承诺“一键直达”。
- 站外平台可能对二维码、站外联系方式、外链和跨平台导流动态调整规则。发布前必须在对应账号的创作中心检查当期规则；若平台没有明确允许的链接组件，使用“完整名称 + 教程内容”而不是规避审核。
- 微信搜索的具体排序权重并未由本次调研确认；不应宣称改名、堆关键词或配置 `sitemap` 能保证排名第一。

## 微信内获客路径

| 路径 | 是否适合现在做 | 用户动作 | 具体做法 | 注意事项 |
|---|---:|---|---|---|
| 微信搜索 | 是，最高优先 | 搜索完整名称并进入正式版 | 统一使用“青缝长图拼接”；简介清楚覆盖“长图拼接、连续截图、自动去重复叠、本机处理”；检查后台“可被搜索”状态及 `sitemap.json` | 不堆无关关键词，不承诺搜索排名 |
| 正式小程序码 | 是，最高优先 | 长按识别或微信扫码 | 所有海报、教程末帧、公众号图片统一放正式小程序码；旁边明确写“长按识别/微信扫码” | 不使用体验版二维码；保持码周围留白和可识别尺寸 |
| 朋友圈海报 | 已经开始，可持续 | 长按小程序码 | 不只发一次产品公告；拆成聊天记录、网页教程、笔记、订单/清单四种场景，分别发前后对比 | 控制频率，不使用夸大或诱导分享文案 |
| 微信群/好友 | 可人工、精准使用 | 看到真实问题后扫码 | 在确有“截图太长、拼接麻烦”的讨论中回复工具海报；先说明用途和本机处理，再给码 | 不做无关群批量投放，不把体验版发给普通用户 |
| 视频号 | 建议 | 看 10–20 秒演示后搜索/扫码 | 发布真实录屏：重叠截图 → 选图 → 自动去重拼接 → 保存；封面和末帧固定显示完整名称和小程序码 | 视频号主页或内容能否原生挂小程序，应在视频号助手按账号权限核验 |
| 公众号 | 有账号再做 | 点击卡片/菜单直达 | 关联小程序；写一篇永久教程；自定义菜单设置“长图拼接”；文章内插入小程序卡片或用正式码 | 公众号关联、菜单类型和图文插入能力以后台实际选项为准 |
| 客服消息 | 适合转化与留存，不是拉新主渠道 | 用户主动咨询 | 首页或结果页放“问题反馈”；准备三条快捷回复：选图顺序、拼接失败排查、隐私说明 | 必须由用户主动发起；不得把客服当群发广告工具 |
| 腾讯广告 | 暂缓，条件成熟后测试 | 广告点击直达小程序 | 先确认广告主资质；只投已经自然验证过的演示素材；落地页直接进入首页，不增加多余中间页 | 先定义转化事件和止损条件；不要仅以曝光量判断效果 |

## 站外平台转化

### 通用原则

对小红书、抖音、B站，默认采用“双路径 CTA”：

> 微信搜索“青缝长图拼接”
>
> 或保存海报后，在微信中长按识别正式小程序码

原因：微信 URL Link/Scheme 是微信侧的拉起能力，但站外平台是否允许、是否可点击、是否被安全页拦截，属于站外平台的发布和广告规则。没有平台明确授权时，不应把普通内容帖子描述成能“一键直达微信小程序”。

### 小红书

- 适合内容：聊天记录整理、旅行攻略保存、学习笔记、网页教程、订单/清单等“连续截图变一张长图”的前后对比。
- 标题结构：`痛点 + 结果`，例如“聊天记录截图太碎，我用 20 秒拼成了一张长图”。
- 正文只保留一个核心动作：微信搜索完整名称；若当前账号规则允许二维码图片，再把正式小程序码放在末图。
- 不要在正文堆微信号、外链和重复导流话术；是否允许二维码或站外导流以发布时平台提示为准。

### 抖音

- 适合内容：10–20 秒强演示；前 2 秒直接展示“5 张重叠截图 → 1 张连续长图”。
- 画面内持续出现短品牌名，结尾 2–3 秒显示完整名称和正式小程序码。
- 普通视频文案中的 URL 不应被当成可靠直达路径；若账号获得平台批准的链接组件或广告能力，再按该能力的规则配置。
- 每个视频只测试一个场景，不在一条视频内同时讲所有功能。

### B站

- 适合内容：1–3 分钟完整教程、不同机型/不同截图类型测试、自动拼接原理的非技术解释。
- 简介、置顶评论和结尾口播统一使用完整名称；小程序码放在视频末帧或动态配图时，先核对当前社区与商业推广规则。
- “蓝链”、商业推广落地页等并非普通投稿账号默认具备的能力，不应当作零成本通用入口。

## 提高转化率的内容与产品动作

### 1. 先把信息统一

所有渠道固定使用以下信息，不再创造多个叫法：

- 产品名：`青缝长图拼接`
- 功能句：`2–20 张连续截图，自动识别重叠并拼成长图`
- 隐私句：`图片仅在本机处理，不上传服务器`
- 行动句：`微信搜索“青缝长图拼接”，或长按识别小程序码`

朋友圈现有文案中的“自动去重”建议改成“自动识别重叠并拼接”，更准确，也更接近用户看到的实际结果。

### 朋友圈首发素材复盘

当前首发已经具备完整名称、功能说明、隐私承诺和正式小程序码，可以保留。后续不要原样重复发布，应改成单一场景的结果演示：

- 开头不要再写“我做了一个小程序”，直接写用户问题，例如“聊天记录截了 8 张，发给别人时重复又容易乱序”；
- 主视觉使用同一组截图的拼接前后对比，优先用 10—15 秒录屏而不是纯公告海报；
- 每条只讲一个场景，结尾保留同一个完整名称和正式小程序码；
- 小程序码周围保持留白，并在真机朋友圈中实际长按一次确认能识别；
- 不要求用户转发，不使用“求支持、转发解锁”等诱导表达。

### 2. 一条内容只解决一个场景

首轮只测试四个场景：

1. 聊天记录连续截图；
2. 网页教程/攻略；
3. 学习笔记；
4. 订单、清单或行程信息。

每条内容结构固定为：

> 痛点截图（2 秒）→ 选择 2–20 张（3 秒）→ 自动拼接（5 秒）→ 成品上下滚动（3 秒）→ 产品名、小程序码和隐私承诺（3 秒）

素材中的“拼接前”和“拼接后”必须来自同一组截图，避免再次出现对比内容对不上的问题。

### 3. 降低首次使用阻力

- 用户扫码或搜索进入后，首屏主按钮直接写“选择连续截图”。
- 在按钮下放一行顺序提示：`按从上到下的顺序选择 2–20 张`。
- 第一次成功生成后再解释手动调缝，不要在使用前堆教程。
- 对失败状态给出可执行原因，例如“截图重叠区域太少，请保留约 1/4 屏幕重复内容”。
- 保持“本机处理”表述可见，它既是差异点，也是消除隐私顾虑的转化信息。

### 4. 建立最小数据闭环

在不虚构、不上传用户图片的前提下，每周记录：

- 各平台发布内容数量；
- 各内容的公开曝光、完播/阅读、收藏和评论；
- 微信公众平台中的小程序新增访问人数；
- 首页到首次选图、成功生成、成功保存的可用统计（如后台已有对应分析能力）；
- 用户主动反馈中的失败类型。

核心判断不是“哪个平台点赞多”，而是：

> 哪个场景内容发布后，带来的新增访问与成功完成一次拼接的人数最多。

若目前没有站内步骤级统计，不要先接入会改变隐私边界的图片上传服务。可以先用发布时间窗口、不同平台内容节奏和微信后台新增访问趋势做低精度判断；以后再单独设计合规的匿名事件统计。

## 30 天执行顺序

### 第 1 周：转化基线

- 确认微信能按完整名称搜到正式版。
- 用非管理员普通微信扫码正式小程序码完成一次：进入、选图、拼接、保存。
- 固定一张正确的前后对比海报和一个 15 秒录屏模板。
- 检查后台搜索开关、小程序名称、简介、服务类目和 `sitemap.json`。

### 第 2 周：微信内扩散

- 朋友圈分 3 次发布不同场景，不重复同一公告图。
- 发布 3 条视频号短录屏，每条对应一个使用场景。
- 在真实相关的好友或群对话中做少量精准分享，不群发。
- 汇总用户问得最多的三个问题，整理为客服快捷回复。

### 第 3 周：站外内容矩阵

- 小红书、抖音、B站分别发布适配平台形态的同一场景素材。
- 所有平台保持同名、同隐私句、同正式小程序码。
- 不购买“代发、刷量、批量群发”，不通过规避审核的方式放站外联系方式。

### 第 4 周：只放大有效场景

- 对比“聊天记录/网页教程/笔记/清单”四类内容带来的新增访问趋势。
- 留下最有效的两个场景，各制作三种不同开头继续测试。
- 只有当“进入后能完成一次拼接”已经稳定，才评估小额腾讯广告测试或建立公开落地页。

## SEO 与 GEO

- **微信搜索优化要做，但不是传统网站 SEO。** 重点是名称一致、准确简介、服务类目、页面可索引状态，以及站内外内容反复使用同一完整名称。
- **传统 SEO 不是当前最高优先级。** 小程序本身不是普通搜索引擎网页。若以后建立独立落地页，再围绕“长图拼接、截图拼接、聊天记录拼接、自动去重叠、本机处理”写真实教程和 FAQ。
- **GEO 暂不单独立项。** 先积累可公开引用的产品说明、隐私说明、真实教程、更新记录和 FAQ；这些也是后续 AI 搜索理解产品所需的基础材料。不要制造虚假测评、虚假用户评价或没有证据的“最好用”表述。

## 不建议做的事

- 不用 `0.1.4` 体验版做公众广告落地页。
- 不恢复“分享用户拼接结果”来换裂变；这会重新触发内容安全和隐私边界问题。
- 不在用户尚未主动咨询时使用客服消息做广告群发。
- 不把站外 URL Link/Scheme 描述成所有平台都能直接跳转。
- 不购买刷量、刷搜索、批量群发或虚假评论。
- 不用“永久免费、零失败、100% 自动、绝不读取图片”等无法证明或容易误解的宣传语。
