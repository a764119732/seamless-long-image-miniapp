# 微信小程序分享与低成本推广研究

日期：2026-07-28

## 当前项目证据

- 本地 `0.1.4` 已实现 `onShareAppMessage` 和 `onShareTimeline`，固定分享标题、首页路径及 `/assets/share-card.png` 宣传封面；需上传、审核和发布后才会进入线上版本。
- 项目此前移除的是 `wx.showShareImageMenu`：该接口分享用户生成的拼接结果图片。恢复固定的小程序首页卡片分享与恢复结果图片分享是两件不同的事。
- 产品仍采用本地处理：不上传原图或拼接结果，不提供用户内容发布、评论、社区或公开展示。

## 微信官方能力

- 页面可通过 `Page` 生命周期提供页面转发配置，见微信开放文档 [Page](https://developers.weixin.qq.com/miniprogram/dev/reference/api/Page.html)。
- 小程序可使用小程序码作为扫码入口，见微信开放文档 [获取小程序码](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/qr-code.html)。
- 页面索引规则由 `sitemap.json` 管理，见微信开放文档 [sitemap 配置](https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/sitemap.html)。

当前检索环境无法展开微信开放文档正文；实施前应在微信开发者工具内置文档中再次核对当前基础库对 `onShareAppMessage` 和 `onShareTimeline` 的要求。

## 建议路线

### 第一阶段：微信内冷启动

1. 为首页增加固定标题、固定宣传图和固定首页路径的页面卡片分享。
2. 不把用户选择的原图或拼接结果作为分享图。
3. 从微信公众平台下载正式小程序码，制作一张朋友圈海报。
4. 海报只表达一个价值点：连续截图自动去重并拼成长图。
5. 同时标注完整名称“青缝长图拼接”和“图片仅在本机处理”。
6. 用非管理员、非体验成员账号验证扫码、搜索、选图、拼接和保存。

### 第二阶段：内容平台验证

- 用 10—20 秒真实录屏展示“重复截图 → 选择图片 → 自动拼接 → 成品”。
- 微信生态优先使用小程序卡片或小程序码。
- 其他平台统一使用完整产品名和同一演示素材；外部二维码、联系方式和跨平台导流应以各平台当期规则为准。
- 先发布少量不同使用场景：聊天记录、网页教程、笔记和订单截图，比较哪个场景带来的有效使用最多。

## SEO 与 GEO 判断

- 现阶段不需要投入传统网站 SEO 项目。小程序不是常规公开网页，首要工作是微信内搜索设置、清晰名称、准确描述和真实内容传播。
- 可以做轻量的“微信搜索优化”：完整名称一致、描述覆盖“长图拼接/截图拼接/自动去重”、服务类目准确、保持线上版本可用。
- GEO（生成式引擎优化）不是冷启动优先项。只有在已有公开、可索引的落地页、教程、FAQ 和真实用户反馈后，AI 搜索才有稳定材料可引用。
- 后续若需要站外自然搜索，可建立一个公开落地页，统一提供产品介绍、隐私说明、演示视频、FAQ、小程序码和版本更新时间。

## 最小衡量指标

- 朋友圈或内容帖触达人数。
- 小程序新增访问人数。
- 首次选图人数。
- 成功生成并保存长图的人数。
- 次日或七日再次使用人数。

初期重点不是曝光量，而是“进入小程序后完成一次拼接”的比例。
